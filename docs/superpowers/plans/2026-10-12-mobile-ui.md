# Interfaccia mobile (issue #25) — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Galaxy Map usabile su telefono, in verticale e in orizzontale: gesti
touch (un dito ruota, pinch avanza/zooma), un unico pannello (dal basso in
verticale, da destra in orizzontale) per card, System View, dock e musica.
Desktop invariato.

**Architecture:** una funzione pura `layoutMode` decide `desktop | portrait |
landscape`; `App` espone il valore in `data-layout` e i componenti scelgono la
variante. Il contenuto del pannello unico è derivato dallo stato esistente
(`dockPanel`, `musicExpanded`, selezione, vista) da una funzione pura; il
pannello ha un solo stato nuovo nello store (`sheetSnap`). La logica dei gesti
(pinch) sta in `lib/` con unit test; i componenti si verificano con un nuovo
progetto Playwright mobile (touch emulato, bounding box, axe).

**Tech Stack:** React 19, TypeScript strict, Tailwind 4, zustand,
react-three-fiber/drei, react-i18next, Vitest, Playwright + axe.

**Spec:** `docs/superpowers/specs/2026-10-12-mobile-ui-design.md`

**Branch:** `feat/mobile-ui`

## Global Constraints

- Nessuna dipendenza nuova; versioni pinnate invariate.
- Desktop invariato: con `layoutMode === 'desktop'` DOM e comportamento
  restano quelli di oggi; la suite e2e desktop esistente passa senza modifiche
  ai test (spec AC12).
- Layout mobile solo con `(pointer: coarse)` **e** lato corto < 600 px; 600 px
  è **scelta progettuale (non dato)**.
- Viewport minimo 360 × 640 / 640 × 360: nessun elemento oltre i bordi.
- Un solo pannello aperto per volta.
- Target touch ≥ 44 × 44 px CSS nel layout mobile.
- Ogni costante nuova dichiara unità e natura (**dato**, **scelta estetica
  (non dato)**, **scelta progettuale**, **scelta umana (#25)**).
- Stringhe utente in `en/it/es/fr/de.json`.
- Array grandi mai in state/props (AGENTS.md, trappola 1).
- `data-testid` esistenti invariati; i nuovi sono elencati nei task.
- `prefers-reduced-motion`: niente animazioni del pannello (snap immediato).
- Stelle di test: quelle già usate dagli e2e con le golden fixture
  (`polaris`, `proxima cen`, `trappist`), mai inventate.

## Review Focus

1. **Fine di un pinch:** un dito si alza e l'altro continua a trascinare → la
   vista non salta (e2e in Task 3).
2. **Pinch letto come tap:** alzare le dita a fine pinch sopra una stella non
   la seleziona (e2e in Task 3).
3. **Rotazione del telefono con pannello aperto:** il pannello passa da basso
   a destra, mantiene lo snap, niente esce dal viewport (e2e in Task 4).
4. **Tastiera virtuale della ricerca:** riduce l'altezza (es. 375 × 400): resta
   `portrait`, i risultati restano visibili (unit Task 2, e2e Task 5).
5. **Nome lungo dell'host a 360 px** nell'header della System View: troncato,
   non spinge aiuto/lingua fuori schermo (e2e in Task 6).
